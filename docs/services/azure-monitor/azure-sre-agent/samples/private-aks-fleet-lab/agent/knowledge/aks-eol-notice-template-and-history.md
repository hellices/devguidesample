## 1. AKS 버전 업그레이드 사전 점검 및 공지 작성 4단계 원칙

1. **EOS 도래 버전 및 작업 대상 클러스터 엄격 필터링 (`check-aks-eos-release-calendar`)**:
   - MS Learn 공식 AKS 릴리스 일정 웹페이지를 실시간 파싱하여 지원 종료(EOS/EOL) 예정 버전을 확인한다.
   - `5. 작업 대상 클러스터` 표에는 **이번 업그레이드 공지 대상 마이너 버전(예: `1.34`)과 일치하는 클러스터(`targetUpgradeClusters`)만** 포함하며, 다른 버전(`1.35`, `1.36` 등)을 사용 중인 클러스터는 작업 대상에서 반드시 제외한다.
2. **조회 건수에 따른 K8s / Azure 데이터 조회 도구 선택 기준**:
   - **3건 이하의 단순·단건 조회** (예: 특정 파드 1~2개의 상세 상태, 이벤트, 로그 확인): 내장 **`RunKubectlReadCommand`** (`kubectl get / describe / logs`) 또는 **`RunAzCliReadCommands`** 를 즉시 호출한다.
   - **4건 이상의 다중 리소스·다중 클러스터 복합 조회**: 반복적인 `kubectl` 개별 호출로 인한 지연을 막기 위해, 사전 등록된 Python API 도구(`evaluate-aks-upgrade-preflight`)를 호출하거나 **`DefaultAzureCredential` 기반 Python REST API 조회 코드를 작성·실행**하여 1회 호출로 일괄 수집한다.
3. **버전간 주요 변경 사항 실시간 발췌 (`mslearn-mcp`)**:
   - 고정된 문구를 사용하지 않고, `mslearn-mcp`(`microsoft_docs_search`, `microsoft_docs_fetch`) 및 공식 Kubernetes CHANGELOG를 조회하여 컨트롤 플레인 자동 처리 항목은 제외하고 **사용자가 사전 확인·조치해야 하는 변경사항(노드 OS/런타임, 제거 예정 API, 메트릭·볼륨·네트워크 검증 사항, 주요 GA 기능)** 만 마이너 버전 구간별로 정리한다.
4. **9대 사전 점검 결과의 리포트 필수 포함 (`evaluate-aks-upgrade-preflight`)**:
   - 평상시에는 9대 항목 전체(`check_items="ALL"`), 특정 항목 지정 시에는 해당 번호(예: `check_items="1,3,4"`)만 점검한 뒤, **그 점검 결과를 `5. 작업 대상 클러스터` 표와 하단 `### 5-1. SRE 에이전트 사전 점검 상세 결과` 표에 반드시 포함**한다.

## 2. [표준 양식] 최종 사용자 발송용 AKS 버전 업그레이드 공지 메일 마크다운(`.md`) 템플릿

- **링크 작성 규칙**: 사내 서비스나우 및 Confluence 링크는 하드코딩하지 않고 사용자가 발송 전 직접 입력할 수 있도록 `[직접 입력: ...]` 자리표시자(Placeholder)로 비워둔다.
- **중괄호(`{...}`) 치환 규칙**: 아래 양식의 `{...}` 부분은 형태를 보여주기 위한 자리표시자(예시)이며, 반드시 실시간 도구 호출 결과로 치환하여 출력한다.

```markdown
이 메일은 해당 구독의 주요 담당자 및 권한자에게 발송되었습니다.

# [AKS 클러스터 v{대상_마이너버전} 버전 업그레이드 공지]

AKS 클러스터 v{대상_마이너버전} 버전이 {EOL_연월}부로({EOL_일자_YYYY.MM.DD}) 공식 서포트가 종료됨(EOL)에 따라, 안정적인 서비스 운영을 위해 최신 버전으로 업그레이드 작업이 필요합니다. (*LTS 버전 제외)

서포트가 종료된 버전을 계속 사용하실 경우, 보안 취약점 노출 및 기술 지원 중단 등의 문제가 발생할 수 있으니, 아래 내용 참고하시어 서비스나우에 작업 요청 부탁드립니다.

*작업 일정 관련 - 운영계 버전 업그레이드 작업은 매주 화요일, 목요일 18:00 이후로 작업 희망 일정 등록 부탁드립니다. (별도 사유가 있는 경우 요일 변경 가능합니다.)

*통합 AKS 전환 대상인 단위서비스는 본 버전 업그레이드 작업 대상에서 제외 하였으며, 전환 기간 내 통합 AKS 전환 후 기존 개별 AKS 제거를 부탁드립니다.

## 1. 업그레이드 개요
* **목적**: AKS 클러스터 안정성 및 보안 강화, 최신 기능 지원 및 EOL 버전 사용으로 인한 위험 방지
* **업그레이드 목표 버전**: v{목표_패치버전} (EOL Date: {목표버전_EOL_YYYY.MM.DD})
* **작업 예상 시간**: 1시간 내외 (총 작업 시간은 노드 개수에 의해 변경될 수 있습니다)
* **작업 방식**: v{현재_패치버전} -> v{중간_패치버전} -> v{목표_패치버전} 과 같이 순차적으로 진행
* **예상 영향도**: 업그레이드 진행 중 일시적 서비스 중단 발생 가능하므로 작업 전후 서비스 점검 필요

## 2. 서비스나우 신청 가이드
* **서비스나우 링크**: `[직접 입력: 서비스나우 카탈로그 URL 입력]`
* **요청 제목**: `[대상서비스명/환경(개발/운영) 기재] AKS 클러스터 버전업그레이드 작업 요청(목표버전: v{목표_패치버전})`
* **요청 유형**: `요청유형 1: AKS` / `요청유형 2: AKS 클러스터 변경`
* **요청 내용**:
  - **서비스 오픈 여부 체크 (상용 오픈여부)**: PRD AKS가 상용일 시, DEV AKS도 상용으로 체크 후 서비스나우 등록요청 드립니다.
  - **희망 작업 일정**:
    - 운영계 - 화요일 또는 목요일 18:00 이후
    - 개발계 - 요일 무관, 업무 시간
  - **변경 신청 안내**:
    - 개발(dev)/운영(prd) 각 구독에 대해 클러스터 버전 업그레이드 변경 작업 요청 부탁드립니다.
    - 개발(dev) 환경을 통해 버전 업그레이드의 영향도를 미리 파악하고, 운영(prd) 환경에서 안정적인 업그레이드를 진행해야 합니다.
    - 신규 버전으로 업그레이드 이후 이전 버전으로 롤백은 불가능합니다. 전달드린 가이드의 체크리스트 및 안내사항 등을 미리 확인해주시고 업그레이드 변경 작업 요청 바랍니다.
    - 관련하여 궁금하신 사항이 있으시면 서비스 나우 > Azure 기술문의로 문의 부탁드립니다.
```
